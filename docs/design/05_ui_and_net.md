# 05 · 界面、交互与联机

---

## 1. 界面状态机

在现有状态机（`title / select / ready / play / clear / pause / over / win`）上新增两个状态：

```
... play ──(肃清/坚守完成)──> clear ──> reward ──> (每 3 关) station ──> ready ...
                                            │                              │
                                            └────────> (第 9 关后) ──> win ┘
```

| 状态 | 说明 | 鼠标 | 战场 |
| --- | --- | --- | --- |
| `reward` | 三选一卡牌 | 可见 | 冻结（敌人 AI 已在 `state != "play"` 时停止） |
| `station` | 补给站 | 可见 | 冻结 |

`clear` 保留 3.4 秒的肃清提示，然后自动进入 `reward`。

## 2. 卡牌界面（RunUI · 卡牌模式）

### 2.1 布局（1920×1080 设计空间）

```
┌──────────────────────────────────────────────────────────────┐
│                   第 2 关 肃清 · 选择强化                      │
│                 战功 138    已选 3 张                         │
│                                                              │
│   ┌──────────┐    ┌──────────┐    ┌──────────┐               │
│   │ 稀有      │    │ 常规      │    │ 史诗      │               │
│   │ 吸血装甲  │    │ 快速装填  │    │ 弹幕风暴  │               │
│   │          │    │          │    │          │               │
│   │ 造成伤害  │    │ 装填时间  │    │ 每次击发  │               │
│   │ 的 4% ... │    │ −8%      │    │ +2 发 ... │               │
│   │          │    │          │    │          │               │
│   │ 已持有 1  │    │ 已持有 0  │    │ 已持有 0  │               │
│   └──────────┘    └──────────┘    └──────────┘               │
│                                                              │
│        ←→ 选择    Enter 确认    R 重掷 40     Esc 跳过 +30     │
└──────────────────────────────────────────────────────────────┘
```

- 卡片尺寸 330×400，间距 28，整组水平居中，顶部留 220 px 给标题与状态行。
- 稀有度用卡片顶部 6 px 色条 + 档位文字 + 边框颜色表达，不只靠颜色（色盲友好）。
- 已持有的卡在下方显示"已持有 N 张"，叠满的卡不会出现。
- 不可选（战功不足）时重掷提示变红，按键无效并播放 `dry` 音。

### 2.2 交互

| 输入 | 行为 |
| --- | --- |
| `←/→` 或 `A/D` | 移动光标 |
| `Enter` | 确认选卡 |
| 鼠标移动 | 悬停高亮 |
| 鼠标左键 | 点选并确认 |
| `R` | 重掷（扣战功），不改变光标语义 |
| `Esc` | 跳过，+30 战功 |

### 2.3 联机

客户端进入相同界面，但标题下方追加"等待房主选择"，且所有输入无效；
房主确认后通过可靠 RPC 广播卡 id，客户端应用并关闭界面。

## 3. 补给站界面（RunUI · 补给模式）

- 三行商品列表，每行显示名称、效果、价格、状态。

```
             第 1 战区 · 前线补给站
        战功 210    补给券（结算）1250

   ▶  全面维修    全员回满 + 5 秒护盾        120   [购买]
      战术档案    获得随机稀有卡              180   [战功不足]
      备用车体    本局每人 +1 条命            260   [购买]

   ↑↓ 选择    Enter 购买    Esc 离开
```

- 已购买项显示"已购"，不可重复购买；备用车体是唯一例外，可以反复购买，
  每名玩家最多 5 条命，全部满员后显示"已达上限"。战功不足显示"战功不足"，
  三种状态必须区分开，不能都写成同一句灰字。
- 离开后进入下一关的倒计时。

## 4. 战斗 HUD 增量

在左上角现有"得分 / 关卡 / 连击"区域下方新增一行运行状态条：

```
战区 2/3 · 第 5 关 坚守   战功 138   卡牌 4        [坚守 00:42]
```

- 关卡类型为 `坚守` 时，右上角"剩余敌军"下方显示倒计时；其它类型不显示。
- 战区名与关卡类型同时出现在开场横幅：`第 5 关 · 工业纵深 · 坚守哨点`。
- 连击倍率与现有显示合并，不新增区域。

## 5. 结算页

现有结算页（伤害、命中率、勋章）保留，追加 Run 段落：

```
—— 本次行动 ——
第 2 战区 · 第 6 关        距终点 3 关
选过的强化（6）
  穿甲强化 ×2   快速装填   双联炮座   吸血装甲   战地回收
战功 460 → 补给券 +230（失败转化 50%）

补给券余额 1480        最深抵达 第 6 关
```

规则：

- 胜利显示"全线突破"，失败显示"行动中止"。
- 失败时明确写出 50% 转化，避免玩家以为战功被吞。
- 结算页保留现有键位：`R` 重新出击、`Esc` 回标题。

## 6. 车库（选车）界面

四行结构不变，第三行语义改变：

| 行 | 内容 | 操作 |
| --- | --- | --- |
| 0 | 战车（含解锁状态） | `←/→` 换车，`U` 解锁 |
| 1 | 难度 | `←/→` |
| 2 | 挑战（标准 / 每日 / 精英） | `←/→` |
| 3 | 地形偏好 | `←/→` |

车库下方另列三项永久升级，用 `1/2/3` 购买：`备用车体`、`后勤预算`、`情报网`。
价格与等级上限来自 `Meta.UPGRADES`；已满级显示"已满级"，补给券不足时提示差额。

展示增量：

- 标题下方一行：`补给券 1480   最深抵达 第 6 关   通关 3 次   挑战通关 1 次`。
- 未解锁战车：`【猎手 · 坦克歼击车】未解锁 · 需 800 补给券（U 解锁）`。
- 解锁成功：音效 + 横幅"已解锁 猎手"。
- 出击时若战车未解锁，拦下并提示。

局域网大厅的"关卡"行改为"挑战"：局结构固定 9 关，不再允许从第 N 关开始；
房主在车库选好的挑战会带进房间，大厅里仍可修改。

## 7. 键位汇总（新增部分）

| 场景 | 键 |
| --- | --- |
| 卡牌 / 补给站 | `←/→` / `A/D` 选择，`Enter` 确认，`R` 重掷，`Esc` 跳过或离开 |
| 车库 | `U` 解锁当前战车 |
| 战斗中 | 不变 |

键位全部走现有 `InputSetup` 的动作（`ui_left/right/accept`、`restart`），
不新增物理按键绑定，因此手柄天然可用（`R` 用 `X`，`Esc` 用 `B`）。

## 8. 联机协议

### 8.1 状态同步

`main.net_collect_snapshot()` 的字典新增：

```gdscript
"run": {
    "active": true,
    "stage": 5,
    "kind": 1,              # 0 歼灭 / 1 坚守 / 2 决战
    "credits": 138,
    "cards": ["ap_round", "loader"],
    "offer": ["vampiric", "plate", "annihilator"],
    "rerolls": 1,
    "mutators": ["hardened"],
    "diff": 1,
    "challenge": 0,
}
```

`diff` 与 `challenge` 必须一起下发：客户端要靠 `challenge` 算每日挑战的 1.1 倍转化，
靠 `diff` 显示正确难度。只发 `mutators` 会让客户端结算页与房主差 10%。

客户端 `net_apply_snapshot()` 应用该行并重算 `Run.mods`，于是客户端本地车拥有相同的卡牌加成
（位置仍由客户端权威、房主校验，伤害一律房主结算）。

### 8.2 事件

| RPC | 方向 | 内容 |
| --- | --- | --- |
| `net_run_offer(offer, stage)` | 房主 → 客户端（可靠） | 打开三选一界面 |
| `net_run_event("card", {id})` | 房主 → 客户端（可靠） | 选了哪张卡 |
| `net_run_event("skip", {})` | 房主 → 客户端（可靠） | 跳过并领取补偿 |
| `net_run_event("withdraw", {})` | 房主 → 客户端（可靠） | 坚守结束，场上敌人撤退（不计击杀、不留残骸） |
| `net_run_event("station_open", {...})` | 房主 → 客户端（可靠） | 打开补给站 |
| `net_run_event("station_buy", {...})` | 房主 → 客户端（可靠） | 买了哪项、余额、商品状态 |
| `net_run_event("advance", {stage})` | 房主 → 客户端（可靠） | 进入下一关 |

### 8.3 权威边界

| 内容 | 权威 |
| --- | --- |
| 卡池抽取 | 房主 |
| 选卡 / 重掷 / 购买 | 房主 |
| 伤害、击毁、拆墙、掉落 | 房主 |
| 玩家位置 | 客户端（房主校验） |
| 表现（特效、音效、界面） | 各自本地 |

## 9. 文案规范

- 卡牌名 2–4 字，效果一句话，数值用阿拉伯数字。
- 不使用"显著""大量"等模糊词。
- 负面效果必须写在正效果之后，用逗号分隔：`伤害 +20%，结构 −10%`。
- 补给站商品名 4 字，效果 6–12 字。
