# 03 · 经济与元进度

---

## 1. 两套货币

| 货币 | 作用域 | 获得 | 消耗 | 存档 |
| --- | --- | --- | --- | --- |
| 战功（Credits） | 单局 | 关卡奖励、击杀、跳过卡牌 | 重掷、补给站 | 随 Run 结束清空 |
| 补给券（Meta Credits） | 永久 | Run 结算转化 | 解锁战车、永久升级 | `user://meta.cfg` |

分开的理由与 `Settings` / `Stats` 一致：一局的临时资源不该写进长期存档，
长期成长也不该被"这一局打得差"清零。

---

## 2. 局内战功公式

### 2.1 获得

| 来源 | 数量 |
| --- | --- |
| 肃清 / 坚守完成 | `30 + stage × 8`（第 1 关 38，第 9 关 102） |
| 击毁侦察 | 2 |
| 击毁中型 | 3 |
| 击毁重型 | 5 |
| 击毁火炮 | 6 |
| 击毁 Boss | 15 |
| 跳过卡牌 | `+30`（见 2.3） |

所有来源在入账时乘 `mods.credits`（战功勋章、战地回收、全面改装不含战功）。

### 2.2 消耗

| 行为 | 价格 |
| --- | --- |
| 重掷卡牌 | `40 + 20 × floor(已选卡数 / 3)`（第 1 关 40，后期 100 左右） |
| 补给站 · 全面维修 | 120 |
| 补给站 · 战术档案（随机稀有卡） | 180 |
| 补给站 · 备用车体（+1 命） | 260 |

价格**不随关卡上涨**：补给站的吸引力应该来自"买得起什么"，而不是"越买越贵"。
重掷价格随进度上涨，是为了防止玩家无限刷同一批卡。

### 2.3 跳过

跳过卡牌不是零收益：给 `+30` 战功。理由：

- 三张卡都是废物时，玩家需要一条"换成补给"的路，而不是被迫污染构筑；
- 30 战功约等于半次重掷，跳过的机会成本仍然清晰。

### 2.4 结算转化

| 结果 | 转化率 |
| --- | --- |
| 通关（第 9 关） | 100% |
| 失败 | 50% |
| 每日挑战 | 额外 ×1.1 |

结算公式：`补给券 = floor(剩余战功 × 转化率 × 每日系数)`。
**剩余战功**指结算时未花掉的战功；已花掉的部分已经变成卡牌与补给，不再返还。

## 3. 补给站

- 触发：第 3 关与第 6 关肃清后，打完卡牌三选一之后出现。
- 形式：三件商品，`←/→` 选择、`Enter` 购买、`Esc` 离开。
- 购买后商品置灰，可继续购买其余商品，也可直接离开。
- 联机：房主购买，客户端只显示。

| 商品 | 价格 | 效果 |
| --- | ---: | --- |
| 全面维修 | 120 | 所有存活玩家回满结构，并获得 5 s 护盾 |
| 战术档案 | 180 | 立即获得一张随机稀有/史诗卡（不占三选一机会，仍遵守叠加上限） |
| 备用车体 | 260 | 本局每名玩家 +1 条命 |

设计意图：补给站把"要不要现在变强"变成一个真实的取舍——留着战功结算，还是当场花掉。

## 4. 长期成长

### 4.1 战车解锁

初始只解锁 **游隼**。其余四台用补给券解锁，价格按"上手难度 × 强度"排：

| 战车 | id | 价格 | 定位 |
| --- | --- | ---: | --- |
| 游隼 | `falcon` | 0（默认） | 主战，全能 |
| 山猫 | `lynx` | 350 | 侦察，最快 |
| 铁砧 | `anvil` | 650 | 突破，最硬 |
| 雷锤 | `thunder` | 700 | 支援，高爆 |
| 猎手 | `hunter` | 800 | 歼击，最高单发 |

未解锁的战车仍然可以在车库里查看模型与属性卡（让玩家知道自己在攒什么），
但出击时会被拦下并提示所需补给券。

### 4.2 永久升级

| 键 | 名称 | 效果 | 等级 | 价格 |
| --- | --- | --- | ---: | --- |
| `lives` | 备用车体 | 每局 +1 条命 | 2 | 600 / 1400 |
| `credits` | 后勤预算 | 开局 +80 战功 | 2 | 400 / 900 |
| `reroll` | 情报网 | 重掷价格 −15%（每级，两级共 −30%） | 2 | 350 / 800 |

设计意图：三条升级分别对应"容错 / 起步 / 构筑自由度"，不做纯数值堆叠，
避免元进度把局内决策压平。

### 4.3 记录

`meta.cfg` 同时记录：`runs`、`wins`、`best_stage`、`challenge_clears`、`last_daily`。
车库与标题页显示"补给券余额"与"最深抵达战区"。

## 5. 存档格式

### 5.1 `user://meta.cfg`

```ini
[meta]
credits=1250
runs=12
wins=3
best_stage=9
challenge_clears=1

[tanks]
rows={"falcon": true, "lynx": true}

[upgrades]
rows={"lives": 1, "credits": 0, "reroll": 2}
```

- 所有读取都带默认值；损坏的字典直接回落到空表（与 `Stats` 相同的容错策略）。
- 未知战车 id / 未知升级键一律忽略，不阻塞启动。
- 价格表是代码常量，不写进存档，改价格不会让旧存档失效。

### 5.2 与 `stats.cfg` 的分工

| 文件 | 内容 | 写入时机 |
| --- | --- | --- |
| `settings.cfg` | 我怎么玩（显示、音量、灵敏度、选车） | 每次改设置 |
| `stats.cfg` | 我打得怎么样（命中率、伤害、击毁、最高分） | 每局结束 |
| `meta.cfg` | 我解锁了什么（补给券、战车、永久升级） | 结算 / 解锁时 |

三者互不覆盖；"恢复默认设置"不会清掉成长，"清空战绩"也不会退还补给券。
