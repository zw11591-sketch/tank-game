# 02 · 强化卡牌

---

## 1. 卡牌在流程中的位置

- 每关肃清（或坚守计时归零）后，弹出 **三选一**。
- 玩家用 `←/→` 选卡、`Enter` 确认；`R` 花战功重掷；`Esc` 跳过并领取补偿战功。
- 选中的卡立即生效：修改 `Run.mods`，随后应用到**所有存活玩家**，并在后续重生时继续生效。
- 卡牌在一局内不可撤销，叠加到上限后不再出现在卡池。

---

## 2. 稀有度

| 档 | 名称 | 权重 | 颜色 | 设计意图 |
| --- | --- | ---: | --- | --- |
| 0 | 常规 | 60 | 灰白 `#B9C2CE` | 稳定的数值成长 |
| 1 | 稀有 | 30 | 蓝 `#5AA9F0` | 改变打法的行为卡 |
| 2 | 史诗 | 10（+2×战区） | 金 `#F0B24A` | 一局一张就够强的构筑核心 |

**保底规则**：从第 2 关起，若三张都是常规卡，把第三张替换为随机稀有或史诗。
**去重规则**：同一批三张不重复；已达叠加上限的卡不进入卡池。
**权重修正**：困难难度史诗权重 +5；每日挑战战功 ×1.1。

## 3. 属性修正语义

卡牌的效果统一写成 `mods` 字典，由 `Run.recompute()` 累加。两类键：

### 3.1 乘性键（默认 1.0，卡牌值相乘）

| 键 | 作用点 | 说明 |
| --- | --- | --- |
| `damage` | `Tank.damage` | 单发基础伤害 |
| `reload` | `Tank.reload_time` | **小于 1 才是变快**（0.92 = 装填快 8%） |
| `hp` | `Tank.max_hp` 与出生满血 | 结构上限 |
| `armor` | `armor_front/side/rear` | **小于 1 才是变硬**（0.92 = 受伤减 8%） |
| `speed` | `Player._base_speed` | 极速 |
| `turn` | `Player._base_turn` | 车体转向 |
| `turret` | `Tank.turret_speed` | 炮塔回转 |
| `he` | `Tank.he_mult` | 高爆直击 |
| `splash` | `Tank.he_splash` | 高爆溅射半径 |
| `credits` | 战功收入 | 关卡、击杀、补给站返还 |
| `combo_window` | 连击窗口 | `COMBO_WINDOW × 值` |

### 3.2 加性键（默认 0，卡牌值相加）

| 键 | 作用点 | 说明 |
| --- | --- | --- |
| `ricochet` | `Tank.ricochet_angle` | **降低跳弹阈值角**，单位度；45° → 40° 表示更硬的正面 |
| `lifesteal` | 造成伤害后的回血比例 | 0.04 = 4% |
| `cdr` | 冲刺 / 烟雾冷却 | 0.15 = 冷却 −15% |
| `spawn_shield` | 出生护盾秒数 | 与现有的 3 s 重生护盾叠加取大 |
| `shells` | `Tank.extra_shells` | 每次击发额外弹丸数（0/1/2） |
| `stage_heal` | 每关开始回复比例 | 0.20 = 回 20% |
| `lives` | 本局命数 | 只影响开局 |

### 3.3 标记键（布尔）

| 键 | 效果 |
| --- | --- |
| `kill_explode` | 击毁敌车时在原地引发 6 m、`60 + 0.35×最大HP` 的爆炸（不伤玩家） |

## 5. 抽卡算法

```
候选 = 卡池中 counts[id] < max 的卡
重复 3 次：
    按 (稀有度权重 × 难度修正) 加权抽 1 张，抽中即从候选移除
若 stage ≥ 2 且三张都为常规：
    第三张 = 从稀有 + 史诗候选中加权抽 1 张（若还有）
返回三张（不足时按实际数量返回，最少 1 张）
```

随机源是本局的 `RandomNumberGenerator`，种子由 Run 开始时确定；联机时只有房主抽卡，
客户端通过事件同步，因此两边看到的卡完全一致。

---

## 6. 设计约束（后续加卡时必须遵守）

1. **每张卡必须有代价或取舍**，纯正收益卡只能出现在常规档且数值 ≤ 15%。
2. **乘性卡不允许叠到"无冷却"**：`reload` 连乘下限由 `Run` 钳到 0.35。
3. **行为卡（shells / kill_explode / lifesteal）最多 1~2 张**，避免一局变成特效表演。
4. **卡面文案必须写清数值与方向**，不写"显著提升"这类模糊词。
5. 新增卡必须同时更新 `UpgradeCards.CARDS`、本文档表格与 `RunProbe` 的完整性检查。
