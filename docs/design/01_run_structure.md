# 01 · 局结构与关卡

---

## 1. 一局的结构

```
标题
 └─ 出击（车库：选车 / 难度 / 挑战 / 地形偏好）
     └─ Run 开始：9 关，3 战区
         ├─ 第 1 关  歼灭         → 三选一强化
         ├─ 第 2 关  坚守         → 三选一强化
         ├─ 第 3 关  决战（Boss） → 三选一强化 → 补给站
         ├─ 第 4~8 关 同上循环
         └─ 第 9 关  决战（终局 Boss）
             ├─ 胜利 → Run 结算（战功 100% 转化）
             └─ 失败（命尽 / 基地被毁）→ Run 结算（战功 50% 转化）
```

- 关数固定 9，不再提供"从第 N 关开始"（那是旧的一次性通关结构）。
- 车库第三行由"关卡"改为"挑战"，第四行仍是"地形偏好"。
- 失败条件保持现状：**全员命尽** 或 **基地被毁**。
- 命数：基础 3 条，可被元升级与传奇卡提升；每人独立计数，共享基地。

## 2. 战区

| # | 战区 | 关卡 | 主题 | 敌人成长（HP / 伤害） |
| --- | --- | --- | --- | --- |
| 1 | 边境哨线 | 1–3 | 开阔、掩体少，教玩家读装甲与弹种 | ×1.00 / ×1.00 |
| 2 | 工业纵深 | 4–6 | 水道、货箱、近距离巷战 | ×1.15 / ×1.08 |
| 3 | 核心要塞 | 7–9 | 长墙回廊、Boss 压轴 | ×1.30 / ×1.16 |

战区的作用是给"随机地图"一个可读的叙事框架，并让难度曲线有明确台阶。
战区倍率作用在敌人 HP 与伤害上（与现有 `Enemy.configure` 的关卡成长叠加）。

---

## 3. 关卡类型（Stage Kind）

每个战区的三关固定为 **歼灭 → 坚守 → 决战**，保证每战区都有节奏变化。

### 3.1 歼灭（CLEAR）

- 目标：清空本关投放的全部敌人。
- 沿用现有 `_build_spawn_queue()`：`min(26, 9 + stage×2)` 个敌人，按关卡解锁侦察 / 中型 / 重型 / 火炮。
- 同屏上限沿用 `_net_max_active()`（单机 `min(2 + stage/2, 6)`，联机每多一人 +1，最多 8）。

### 3.2 坚守（HOLD）

- 目标：在据点坚持 `hold_seconds()` 秒；计时归零即过关。
- 敌人**持续投放**：当前队列清空后自动补一波（不追加 Boss）。
- 计时归零时，场上敌人集体撤退（`queue_free`，不计击杀、不掉落）。
- 基地仍可被打爆，失败条件不变。
- `hold_seconds(stage) = 45 + stage × 3`（第 2 关 51 s，第 8 关 69 s）。

### 3.3 决战（BOSS）

- 目标：清空全部敌人，其中包含一台 Boss。
- Boss 数值沿用 `Enemy.configure(4, stage, diff)`：基础 1100 HP、130 伤害。
- 第 3 关 Boss 额外获得 ×1.15 HP、×0.9 装填（战区一的"教学 Boss"）。
- 第 9 关 Boss 额外获得 ×1.35 HP、+1 词缀，并在出场时广播横幅。

## 4. 敌人投放与成长

保留现有的四类普通敌人（侦察 / 中型 / 重型 / 火炮）。投放比例按关卡：

| 关卡 | 侦察 | 中型 | 重型 | 火炮 |
| --- | ---: | ---: | ---: | ---: |
| 1–2 | 58% | 42% | — | — |
| 3–4 | 42% | 32% | 26% | — |
| 5–6 | 30% | 32% | 26% | 12% |
| 7–9 | 26% | 30% | 26% | 18% |

规则细节：

- 数量：`min(26, 9 + stage×2)`，再乘 Run 修正 `horde`（+25%）。
- 关卡成长沿用 `Enemy.configure` 的 `HP ×(1 + min(stage-1,7)×0.09)`、`伤害 ×(1 + min(stage-1,7)×0.05)`。
- 战区倍率在 `configure` 之后乘一次（HP 与伤害）。
- 合作加成沿用现状：每多一名玩家 HP +30%，同屏上限 +1。

## 5. 难度

沿用三档难度（简单 / 普通 / 困难），只改 AI 手感与乘数，不改变关卡结构：

| 难度 | 散布 | 反应延迟 | 提前量系数 | HP 乘数 | 玩家 HP 乘数 | 玩家装填乘数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 简单 | 3.2° | 0.75 s | 0.35 | ×0.90 | ×1.25 | ×0.84 |
| 普通 | 1.9° | 0.45 s | 0.75 | ×1.00 | ×1.00 | ×1.00 |
| 困难 | 1.0° | 0.20 s | 1.00 | ×1.15 | ×0.83 | ×1.21 |

额外：困难难度下卡牌稀有度权重 +5（更容易出史诗），作为补偿。

## 6. 时间预算

| 阶段 | 时长 |
| --- | --- |
| 关卡倒计时 | 2.6 s |
| 歼灭关 | 90–150 s |
| 坚守关 | 51–69 s |
| Boss 关 | 90–120 s |
| 三选一 | 玩家自行决定，无倒计时 |
| 补给站 | 玩家自行决定，无倒计时 |
| **整局** | **约 20–25 分钟** |

调参原则：如果一局超过 30 分钟，先削敌人数量，不要削关卡类型。

---

## 7. 联机（局域网合作）

- 房主是唯一权威：关卡类型、卡池、战功、补给站购买、结算全部由房主结算。
- 客户端跟随：`net_snapshot` 携带 Run 行（关卡、战功、卡牌、当前界面状态），客户端只显示。
- 三选一与补给站界面在客户端可见但**不可点**，显示"等待房主选择"。
- 卡牌对**所有玩家生效**（共享卡池），这是 v1 的明确取舍：实现简单、合作目标一致。
- 断线重连与房主迁移仍不做（与现状一致）。

## 8. 与旧结构的兼容

- `MAX_STAGE` 常量改为 9，HUD 的"关卡 N / 9"自动跟随。
- 旧的 `_sel_stage` 不再参与开局，保留字段避免大范围改动，但车库不再暴露。
- 存档：`user://settings.cfg` 的 `game/selected_tank` 继续使用；新增 `user://meta.cfg`。
- `Stats`（`user://stats.cfg`）继续记录单局与生涯数据，结算页合并展示。
