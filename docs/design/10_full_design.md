## 1. 设计支柱

| 支柱 | 含义 | 反例 |
| --- | --- | --- |
| 战斗优先 | 一切成长最终都体现在"怎么打"上 | 纯数值堆叠、无关小游戏 |
| 选择有代价 | 每张卡都有明确的得失 | 无条件正收益卡 |
| 读得懂 | 效果能从 HUD、音效、画面直接读懂 | 隐藏概率、看不见的加成 |
| 失败也有收获 | 战功必定转化 | 空手而归 |
| 合作共享 | 2~4 人共享同一局与同一份成长 | 各自独立跑一局 |

改动任何数值前先问：它让玩家多做了一个决定，还是只让数字变大了。只有后者就不做。

## 2. 一局（Run）

### 2.1 状态机

```
title
 └─(出击)→ ready ─(2.6 s)→ play ─(目标达成)→ clear ─(3.4 s)→ reward
                                                          ├─(非战区末尾)→ advance → ready
                                                          └─(战区末尾)→ station → advance → ready
play ─(全员命尽 / 基地被毁)→ over        （战功 50% 转化）
play ─(第 9 关目标达成)→ win             （战功 100% 转化）
```

- `reward` / `station` 是**冻结**，不是暂停：不调用 `get_tree().paused`，否则联机快照会断。
- 冻结期间敌人 AI 因 `state != "play"` 停止；玩家 `controllable == false`，只做惯性衰减。
- 中途退出（暂停菜单回标题）按失败结算，避免"打不过就退"绕过 50% 转化。

## 3. 卡牌

### 3.1 稀有度与抽卡

| 档 | 名称 | 基础权重 | 史诗额外权重 | 颜色 |
| --- | --- | ---: | --- | --- |
| 0 | 常规 | 60 | — | `#B9C2CE` |
| 1 | 稀有 | 30 | — | `#5AA9F0` |
| 2 | 史诗 | 10 | 每深入一个战区 +2，困难再 +5 | `#F0B24A` |

```
候选 = 卡池中 counts[id] < max 的卡
重复至多 3 次：
    在候选中按稀有度权重加权抽 1 张，抽中即从候选移除
若 stage ≥ 2 且三张均为常规且候选仍有稀有/史诗：
    第三张替换为加权抽到的稀有/史诗
返回三张（候选不足时按实际数量返回，可能为 0）
```

随机源是本局的 `RandomNumberGenerator`（种子在 `begin_run` 时确定），不使用全局 `randf()`。
联机时只有房主抽卡，客户端通过事件同步，所以两边看到的三张完全一致。

### 3.2 修正语义

卡牌效果统一写成 `mods` 字典，由 `Run.recompute()` 累加。`recompute()` 是**唯一写入点**。

乘性键（默认 1.0，卡牌值相乘）：

`damage reload hp armor speed turn turret he splash credits combo_window`

- `reload < 1` 表示装填变快；连乘后钳到 `>= 0.35`。
- `armor < 1` 表示受伤减少。

加性键（默认 0，卡牌值相加）：

`ricochet lifesteal cdr spawn_shield shells stage_heal lives`

- `ricochet` 是"把跳弹阈值往下拉多少度"，最终钳到 `[24°, 基线]`。
- `shells` 上限 2。

标记键：`kill_explode`。

## 4. 经济

### 4.1 两套货币

| 货币 | 作用域 | 获得 | 消耗 | 存档 |
| --- | --- | --- | --- | --- |
| 战功 Credits | 单局 | 关卡奖励、击杀、跳过卡牌 | 重掷、补给站 | 随 Run 结束失效（保留供结算页显示） |
| 补给券 Meta Credits | 永久 | 结算转化 | 解锁战车、永久升级 | `user://meta.cfg` |

### 4.2 战功

获得：

| 来源 | 数量 |
| --- | --- |
| 肃清 / 坚守完成 | `30 + stage×8`（第 1 关 38，第 9 关 102） |
| 击毁侦察 / 中型 / 重型 / 火炮 / Boss | `2 / 3 / 5 / 6 / 15` |
| 跳过卡牌 | `+30` |

入账时乘 `mods.credits × blitz 的 1.2`（跳过补偿除外）。

消耗：

| 行为 | 价格 |
| --- | --- |
| 重掷卡牌 | `(40 + 20×floor(已选卡数/3)) × 情报网折扣` |
| 补给站 · 全面维修 | 120 |
| 补给站 · 战术档案 | 180 |
| 补给站 · 备用车体 | 260 |

补给站价格不随关卡上涨；重掷价格随进度上涨，防止无限刷同一批卡。

### 4.3 补给站

- 触发：第 3 / 6 关肃清、且打完三选一之后。
- 全场三件商品；前两件一次性，备用车体可反复买，每名玩家上限 5 条命。
- 三种状态必须区分：可购买 / 已购 / 战功不足 / 已达上限。
- 联机：房主购买，客户端只显示。

| 商品 | 价格 | 效果 |
| --- | ---: | --- |
| 全面维修 | 120 | 所有存活玩家回满结构，并获得 5 s 护盾 |
| 战术档案 | 180 | 立即获得一张随机稀有 / 史诗卡，不占三选一机会，仍遵守叠加上限 |
| 备用车体 | 260 | 本局每名玩家 +1 条命 |

### 4.4 结算转化

```
补给券 = floor(结算时剩余战功 × 转化率 × 每日系数)
转化率：通关 100%，失败 / 中途退出 50%
每日系数：每日挑战 ×1.1
```

已花掉的战功已经变成卡牌与补给，不再返还。结算页必须写出转化率，避免玩家以为战功被吞。

## 6. 战斗规则

### 6.1 确定性跳弹

```
AP 弹 + 命中正面（入射角 < 55°）+ 入射角 > ricochet_angle
    → 零伤害，反馈"跳弹"
```

- 玩家 `ricochet_angle` 默认 45°；卡牌 `ricochet` 只向下拉，最终钳到 24°。
- 敌车按车型分化（`Enemy.ENEMY_RICOCHET`）：侦察 52° / 中型 46° / 重型 38° /
  火炮 50° / Boss 40°。阈值越低正面越硬：重甲与 Boss 的正面甩炮会被弹开，
  侦察与火炮则正面照穿。客户端复制品走同一个 `configure()`，两端判据一致。
- `is_ricochet_angle()` 与 `take_hit()` 共用同一判据，准星提示不会撒谎。
- HE 永不跳弹。

### 6.2 伤害结算顺序

```
1 护盾：shield_t > 0 → 挡下，零伤害
2 分区：按入射角取 正面 / 侧面 / 背面 倍率
3 跳弹：正面 + AP + 角 > 阈值 → 零伤害
4 附加装甲：armor_buff_t > 0 → ×0.6
5 卡牌 armor：已乘进 armor_front/side/rear（apply_run_mods）
6 敌方受伤系数：damage_taken_mult()（硬化、重甲）
7 伤害 = round(基础 × 分区 × 附加装甲 × 敌方系数)；扣血 → 反馈 → 击毁判定
8 射手吸血：on_damage_dealt()
```

## 7. 界面与交互

### 7.1 三选一

- 标题：`第 N 关 · 关卡类型 · 选择强化`；副标题：`战功 X    已选 N 张`。
- 三张卡横排，卡片 330×400（按可用宽高收缩），顶部 6 px 稀有度色条 + 档位文字 + 边框。
- 底部显示"已持有 N 张"；叠满的卡不会出现。
- 输入：`←/→` 或 `A/D` 移动，`Enter` 确认，鼠标悬停 / 点击，`R` 重掷，`Esc` 跳过 +30。
- 战功不足时重掷提示变红，按键无效并播放 `dry`。
- 联机：客户端只读，底部显示"等待房主选择"。

### 7.2 补给站

- 标题：`战区名 · 前线补给站`；副标题：`战功 X    补给券（结算）Y`。
- 三行商品：名称、效果、价格 / 状态。
- 输入：`↑↓` 选择，`Enter` 购买，`Esc` 离开。

### 7.3 战斗 HUD

左上角在"得分 / 关卡 / 连击"下方新增一行：

```
战区 2/3 · 第 5 关 坚守    战功 138    卡牌 4
```

坚守关在右上角"剩余敌军"下方显示 `坚守 MM:SS`，最后 10 秒转红；其它类型不显示。

### 7.4 结算页

保留原有伤害 / 命中率 / 勋章，追加：

```
—— 本次行动 ——
战区名 · 第 N 关    全线突破 / 距终点 N 关
选过的强化（6）  ...
行动修正        ...
战功 460 → 补给券 +230（中途结束 转化 50%）
补给券余额 1480        最深抵达 第 6 关
```

### 7.5 车库

四行：战车（含解锁状态）/ 难度 / 挑战 / 地形。
下方三项永久升级用 `1/2/3` 购买；`U` 解锁当前战车。
显示补给券余额、最深抵达、通关次数、挑战通关次数。

### 7.6 键位

| 场景 | 键 |
| --- | --- |
| 三选一 / 补给站 | `←/→` / `↑↓` 选择，`Enter` 确认，`R` 重掷，`Esc` 跳过或离开 |
| 车库 | `U` 解锁，`1/2/3` 买升级 |
| 战斗 | 不变 |

全部走现有 `InputSetup` 动作（`ui_left/right/up/down/accept/cancel`、`restart`），手柄天然可用。

### 8.2 快照行

`main.net_collect_snapshot()` 的 `run` 键：

```gdscript

    "active": true, "stage": 5, "kind": 1, "credits": 138,
    "cards": ["ap_round", "loader"], "offer": [...], "rerolls": 1,
```

`diff` 与 `challenge` 必须一起下发：客户端要靠 `challenge` 算每日 1.1 倍转化，靠 `diff` 显示难度。

`Run.apply_row()` 先做签名比较，内容没变不重算 `mods`（避免 25 Hz 快照反复按比例回填血量）。

## 9. 技术结构

### 9.1 文件

| 文件 | 类型 | 职责 |
| --- | --- | --- |
| `scripts/upgrade_cards.gd` | `UpgradeCards` | 30 张卡、稀有度、抽卡、累加（纯函数） |
| `scripts/run_state.gd` | autoload `Run` | 单局状态与全部公式，不引用节点 |
| `scripts/meta_progress.gd` | autoload `Meta` | 补给券、解锁、升级、生涯记录 |
| `scripts/mutators.gd` | `Mutators` | 6 条修正与挑战生成 |
| `scripts/enemy_affix.gd` | `EnemyAffix` | 5 种词缀的掷取、数值与表现 |
| `scripts/run_ui.gd` | `RunUI` | 三选一与补给站覆盖层，只发信号 |
| `scripts/main.gd` | 协调器 | 状态机、投放、结算、联机转发 |
| `scripts/tank.gd` | 基类 | 跳弹阈值、多弹、卡牌重算、伤害回调 |
| `scripts/player.gd` | 玩家 | 极速 / 转向 / 冷却从名册基线重算 |
| `scripts/enemy.gd` | 敌人 | 词缀字段与钩子 |
| `scripts/hud.gd` | HUD | Run 状态条与坚守倒计时 |
| `scripts/net.gd` | autoload `Net` | Run 事件 RPC、多弹数 |

### 9.2 数据流

```
Meta ──读解锁/升级/补给券──> main._confirm_start()
                               └─> Run.begin_run(tank, diff, challenge)
                                     ├─ mutators = Mutators.for_challenge()
                                     └─ mods = UpgradeCards 累加
main._spawn_player ──> Player._apply_roster → apply_difficulty → apply_run_mods
main._spawn_enemy  ──> Enemy.configure → 合作加成 → 战区/修正 → EnemyAffix
main.on_tank_destroyed ──> Run.award_kill / 殉爆 / 易爆
main.clear ──> Run.roll_offer → RunUI
main.win/over ──> Run.finish → Meta.add_credits
```

### 9.3 不变量

1. `Run.recompute()` 是 `mods` 的唯一写入点。
2. `reload` 连乘后 `>= 0.35`。
3. `apply_run_mods()` 幂等；调用顺序是"落车 → 难度 → 卡牌"。
4. `heal=false` 时按血量比例回填，不白送满血。
5. `ricochet_angle` 落到 `[24°, 基线]`。
6. `main.stage` 与 `Run.stage` 必须同步（`_start_stage()` 写一次，客户端从 `run` 行应用）。
7. 冻结界面不调用 `get_tree().paused`。

## 12. 扩展规则

### 12.1 迭代收口方式

功能迭代只走这一条闭环，避免"文档写了、代码没写"或"写了、没验证"：

```
改代码 → 同步 02/04/10 的数值表 → 补/改探针断言 → 串行跑 09 §5 的复验命令
      → 把结果与任何文字差异登记到 09 §4
```

探针必须**串行**：多个 Godot 进程共用 `.godot` 脚本缓存，并发时会读到半成品并报编译失败。

`RunProbe` 只覆盖纯数据与公式，`RunFlowProbe` 覆盖真实状态机；任何影响到"关卡推进 / 三选一 / 补给站 / 结算"
的改动都必须跑后者，只有数据层探针通过不足以交付。

### 12.2 新增卡牌

1. 必须有代价或取舍；纯正收益卡只能出现在常规档且数值 ≤ 15%。
2. 乘性数值不允许叠到"无冷却"；`reload` 由 `RunState.recompute()` 钳制。
3. 行为卡（`shells / kill_explode / lifesteal`）最多 1~2 张。
4. 卡面文案必须写清数值与方向。
5. 同步更新 `UpgradeCards.CARDS`、`02_cards.md`、本册第 3.3 节与 `RunProbe` 的完整性检查。

新增词缀 / 修正：

- 词缀优先改变**应对方式**，不要只加血；必须在 `EnemyAffix.DEFS` 与 `04_combat_rules.md` 同时登记。
- 修正只作用于敌人与计时，不改玩家数值。

调整平衡：

- 先调敌人数量与投放节奏，最后才动卡牌数值。
- 每次调整后重跑 `RunProbe` 与 `RunFlowProbe`，并同步 `09_delivery_status.md` 的验证结果。
