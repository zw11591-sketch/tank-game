# 04 · 战斗规则调整、敌人词缀与全局修正

---

## 1. 跳弹：从概率改为确定性阈值

### 1.1 现状的问题

旧规则：正面、AP 弹、入射角 > 32° 时，**30% 概率**跳弹。

- 玩家摆出好角度却被打穿，或者姿势很正却意外跳弹，都会归因于"运气"；
- Roguelite 玩家会反复刷局，随机惩罚会被放大成"这把运气差"；
- 卡牌"降低跳弹角"如果只是提高一个概率，玩家无法验证它是否生效。

### 1.2 新规则

```
若 弹种为 AP
且 命中区域为正面（入射角 < 55°）
且 入射角 > 跳弹阈值角（默认 45°）
则 跳弹：零伤害
```

- **完全确定性**：同一角度必然得到同一结果。
- 阈值角是 `Tank.ricochet_angle`，玩家默认 45°，敌人按类型 38°~52°：

  | 车型 | 侦察 | 中型 | 重型 | 火炮 | Boss |
  | --- | ---: | ---: | ---: | ---: | ---: |
  | 阈值 | 52° | 46° | 38° | 50° | 40° |

  数值越低表示正面越硬（入射角超过它即跳弹）：重型与 Boss 用低阈值逼玩家绕侧面，
  侦察与火炮则几乎不导流，正面照穿。载入点 `Enemy.configure()`，客户端复制品同样生效。
- 卡牌 `ricochet` 修正把它往下拉：`阈值 = clamp(45 − Σcard_ricochet, 24, 45)`。
- 准星提示（`is_ricochet_angle`）与结算（`take_hit`）共用同一个阈值，
  提示不再是"可能跳弹"，而是"这一发会跳弹"。

### 1.3 可读性

- 准星压在敌车正面时，角度进入跳弹区则描边换成冷色，提示文案为"跳弹"。
- 玩家侧被跳弹时保持现状：音效 + 受击方向环 + "跳弹"提示。
- HUD 不显示具体角度数字：角度是操作感，不是作业本。

### 1.4 数值影响与补偿

旧规则在 32°~55° 区间的等效跳弹率约 30%，新区间 45°~55° 必然跳弹。
按均匀入射角估算，正面 AP 的有效跳弹率从约 21% 升到约 18%，
整体接近，但**可预测**。因此不需要调整装甲倍率。

## 2. 伤害结算顺序（保持现状，明确写入规格）

```
1. 命中判定：分步射线，1.2 m 一段，先命中谁算谁
2. 护盾：shield_t > 0 → 挡下，零伤害，播放护盾反馈
3. 分区：按入射角取 正面 / 侧面 / 背面 倍率
4. 跳弹：正面 + AP + 角 > 阈值 → 零伤害，播放跳弹反馈
5. 附加装甲：armor_buff_t > 0 → 倍率 ×0.6
6. 伤害：round(基础伤害 × 分区倍率 × 附加装甲 × 卡牌 armor 修正 × 敌人受伤系数)
   —— 敌人受伤系数由 `Tank.damage_taken_mult()` 提供（硬化修正 + 重甲词缀），玩家恒为 1
7. 扣血 → 反馈 → 击毁判定
8. 伤害回调：射手 lifesteal 回血（见 3 节）
```

**卡牌 `armor` 修正乘在分区倍率之后**，顺序写成代码里的注释，避免以后有人插在跳弹之前。

## 3. 卡牌钩子

| 钩子 | 位置 | 行为 |
| --- | --- | --- |
| 吸血 | `Tank.on_damage_dealt(amount)` → `main.on_player_damage_dealt` | 按 `Run.mods.lifesteal` 回复射手（仅房主结算，随快照同步） |
| 殉爆 | `main.on_tank_destroyed`（敌车分支） | 6 m 内敌车受 `60 + 0.35×max_hp` 的 HE 伤害，不伤玩家 |
| 出生护盾 | `main._spawn_player` 之后 | `shield_t = max(3.0, spawn_shield)` |
| 关卡回血 | `main._start_stage` | 存活玩家回复 `max_hp × stage_heal` |
| 多弹 | `Net._spawn_shot_bundle` | `extra_shells` 决定额外弹丸数（1 发 ±2.4°，2 发 ±2.4°/0°） |
| 连击窗口 | `main._combo_t` 赋值 | `COMBO_WINDOW × mods.combo_window` |
| 技能冷却 | `Player._apply_roster` 之后 | `boost_cd_max / smoke_cd_max × (1 − cdr)` |

联机一致性：吸血、殉爆、爆炸伤害只在房主结算；客户端只播表现。

## 4. 敌人词缀

词缀在 `_spawn_enemy` 中、`Enemy.configure` 之后附加，只影响房主那份实体，
客户端通过 `net_spawn_enemy` 的 `affixes` 字段重建同样的表现与数值。

| id | 名称 | 数值效果 | 表现 |
| --- | --- | --- | --- |
| `armored` | 重甲 | 受伤 ×0.72，HP ×1.25，速度 ×0.90 | 钢灰色车底环 + 头顶「重甲」名条 |
| `frenzied` | 狂热 | 装填 ×0.65，HP ×0.80 | 橙红车底环 + 头顶「狂热」名条 |
| `volatile` | 易爆 | 死亡时原地爆炸：半径 6 m，`40 + 8%×max_hp`，伤玩家 | 橙色车底环 + 头顶「易爆」名条；击毁时先爆再留残骸 |
| `shielded` | 护盾 | 出生 5 s `shield_t` | 青色车底环 + 头顶「护盾」名条；复用现有护盾球 |
| `marksman` | 神射 | 瞄准散布 ×0.6 | 紫色车底环 + 头顶「神射」名条 |

表现说明：车底彩色环负责远距离"这辆不一样"，头顶名条负责近距离读出具体词缀。
文字不依赖颜色，色盲玩家也能读；不使用整车重新涂装，避免把模型自带的迷彩与泥污一起洗掉。
词缀多于 1 条时，名条按 `重甲·神射` 的形式拼接。

### 4.1 词缀数量

| 关卡 | 规则 |
| --- | --- |
| 1–2 | 无词缀 |
| 3–5 | 35% 概率 1 个 |
| 6–8 | 70% 概率 1 个，25% 概率 2 个 |
| 9 | 100% 至少 1 个，40% 概率 2 个 |
| Boss | 保底 2 个（第 9 关 3 个） |
| 修正 `elite` | 所有敌人额外 +1 个 |

词缀数量上限 3，同一敌人不重复。

### 4.2 与数值成长的关系

词缀是"读得懂的随机"：玩家看到重甲车就知道要多打侧面，看到狂热车就知道它射得快。
因此词缀优先选**改变应对方式**组合，而不是纯加血：

- 重甲 + 神射 = 远距离点名，逼玩家用烟幕推进；
- 狂热 + 易爆 = 靠近就自爆，逼玩家保持距离；
- 护盾 + 狂热 = 开局冲脸，逼玩家先打盾。

## 5. Run 级修正（Mutator）

在车库第三行选择挑战；每日挑战由日期种子确定 2 个修正。

| id | 名称 | 效果 |
| --- | --- | --- |
| `iron_rain` | 弹雨 | 敌人装填 ×0.88 |
| `horde` | 人海 | 敌人总数 ×1.25 |
| `hardened` | 硬化 | 敌人受到伤害 ×0.88 |
| `elite` | 精英 | 所有敌人额外 +1 词缀 |
| `veteran` | 老兵 | 敌人伤害 ×1.12 |
| `blitz` | 速攻 | 坚守时间 ×0.8，战功收入 ×1.2 |

规则：

- 标准行动不带修正；精英行动固定带 `elite` + 随机 1 个；每日带 2 个随机。
- 修正只影响敌人与计时，不改玩家数值。
- 修正写进 HUD 的开场横幅与暂停菜单说明，玩家随时能查到"这局为什么这么难"。

## 6. 平衡基线

调整卡牌或词缀后，用以下基线自查（普通难度、游隼、无词缀）：

| 指标 | 目标区间 |
| --- | --- |
| 第 1 关通关时间 | 90–120 s |
| 第 3 关 Boss 击杀时间 | 45–70 s |
| 一局总击杀 | 60–90 |
| 一局结束时卡牌数 | 6–9 |
| 通关率（熟练玩家） | 25%–40% |

超出区间的第一反应是调敌人数量与投放节奏，最后才动卡牌数值。
